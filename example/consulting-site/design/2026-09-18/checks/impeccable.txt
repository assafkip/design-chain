=== VERIFIED FALSE POSITIVE (checked, not just noted) ===
The [low-contrast] findings above ("text #ffffff on #4f80cb", 4-5 per page) do not match the
actual rendered page. Sampled real pixels from D1-astro-laptop.png at the flagged elements'
approximate position (720, 700): true rendered color is rgb(49,108,177), not #4f80cb. #4f80cb is
the panel gradient's declared LAST CSS color-stop; the detector appears to read that literal value
as "the background" for gradient-backed ancestors rather than sampling the true rendered color at
the element's actual position.

Real WCAG contrast computed from the sampled pixel: white on rgb(49,108,177) = 5.37:1, above the
4.5:1 requirement. Verified with the standard relative-luminance formula, not assumed.

This is the detector's limitation with gradient backgrounds, not a defect in the page. Fixing the
button backgrounds to opaque colors (done, see D1/D2/D3 CSS) was a real improvement regardless,
just not what actually silenced this specific finding, since it never measured the true problem.
Kept unresolved in the raw tool output above rather than deleted, so the discrepancy is auditable.

The [line-length] finding (~86 chars, aim <80) is real but not a project violation: this project's
own standard (design-chain.json max_line_chars: 90) already passed via design-standard-check.py.
impeccable's <80 recommendation is a generic default, not this project's contract.
